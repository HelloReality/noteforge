(Web & App Security — SQLi, XSS, CSRF, SSRF, API Hardening)
11.Explain SQL Injection and how parameterized queries prevent it.
  • SQL Injection (SQLi) occurs when an attacker inserts malicious SQL code via input fields.
  • Attacker can read, modify or delete data, bypass authentication, escalate privileges, etc.
  • Prevention: use parameterized queries / prepared statements, input validation, least-privilege DB accounts.
Vulnerable Query
SELECT * FROM users
WHERE username = '" + userInput + "'
AND password = '" + pass + "'
Attacker Input:
' OR '1'='1
Result:
Condition always TRUE → Access Granted!
Parameterized Query (Safe)
SELECT * FROM users
WHERE username = ?
AND password = ?
Parameters:
username = userInput
password = pass
Result:
Input treated as data, not code → not executable.
12.What is Cross-Site Scripting (XSS), and how is reflected XSS different from stored XSS?
  • XSS allows attackers to inject malicious scripts into web pages viewed by other users.
  • Reflected XSS: payload is reflected off the server (e.g. in search results, error messages) — usually delivered via a crafted link.
  • Stored XSS: payload is stored on the server (e.g. in DB) and served to every visitor — higher blast radius.

13.What is CSRF, and how do CSRF tokens protect against it?
  • CSRF (Cross-Site Request Forgery) tricks a logged-in user into performing unwanted actions on a web app where they're authenticated.
  • Attacker crafts a malicious link/form that the victim's browser auto-submits with session cookies.
  • CSRF Token — a unique, unpredictable per-session value — ensures the request originated from the legitimate app UI.

14.What is Server-Side Request Forgery (SSRF), and why is it dangerous in cloud environments?
  • SSRF occurs when a server is tricked into making requests to internal or external resources on the attacker's behalf.
  • Attacker can reach internal services, metadata APIs, or bypass firewalls from a trusted vantage point.
  • In cloud, SSRF can lead to credential theft, instance takeover, or full data exposure.

15.How would you secure an API against common attacks such as injection, broken authorization, and abuse?
  • Injection: validate & sanitize inputs, use parameterized queries, enforce strict schema with allow-lists.
  • Broken Auth: OAuth 2.0 / OIDC, short-lived tokens, refresh-token rotation, MFA on sensitive scopes.
  • Abuse: rate-limit per IP & per user, quota headers, WAF, anomaly detection on traffic patterns.
API Security Checklist
